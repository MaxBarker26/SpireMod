Find where a potion belongs.

Your first win: explain which parts of this project would change to add a potion granting 5 energy and drawing to a full hand.

You already know C#. Focus on the responsibilities around your class: how it is loaded, how it participates in gameplay, and how it gets its text and art.

1. Know the layers

LayerResponsibility
GameProvides the content model hierarchy and game operations.
BaseLibExtends game models with modding conveniences, including custom asset paths and ID prefixing.
Your templateProvides project wiring and reusable bases following your mod's asset conventions.
Your concrete contentDefines the specific potion, card, relic, or power you want to add.

Read: BaseLib — Custom Models, especially the introduction and “General Model Info.” Look for the distinction between a model and a Godot node.

Your existing card hierarchy illustrates the layers:

CardModel                 // game
  └─ CustomCardModel      // BaseLib
      └─ EnergyPotionCard // your abstract asset conventions
          └─ YourCard     // future concrete behavior

This is a hierarchy, not a loading sequence. EnergyPotionCard is abstract and implements art paths; it is not a playable card. The relic and power files follow a similar pattern. These observations come directly from your card, relic, and power files.

2. Separate startup from gameplay

Open MainFile.cs. Its [ModInitializer(nameof(Initialize))] identifies the startup method. Inside it, PatchAll(assembly) applies Harmony patches declared in this assembly. Harmony's startup example shows this pattern.

The potion's repeatable effect belongs in its model's activation behavior. We will inspect the installed game to find that exact override and the commands it should call. Startup runs to initialize the mod; it is not the potion-drinking event.

Primary workflow: Modding Basics — Learning how to make things. Read those few paragraphs; look for “models,” lifecycle actions, commands, and adapting comparable game content.

BaseLib offers CustomPotionModel. Your template currently has no concrete potion and no potion-specific art helper. That is the branch we will add later.

3. Locate code, text, and art

The deployed mod uses separate outputs:

EnergyPotion.json  ← identity, dependencies, flags
EnergyPotion.dll   ← compiled C# behavior
EnergyPotion.pck   ← packaged text and assets

Source: Modding Basics — Mod files.

In this workspace, inspect CopyToModsFolderOnBuild and GodotPublish. A normal build copies code, metadata, and debug symbols; the Godot export path packages resources. The quick PCK package is commented out. A code change and an image change therefore need different output checks.

Also distinguish the BaseLib package reference in the project from the BaseLib dependency in the manifest: the former supplies a compile-time reference; the latter declares the mod required at runtime. See BaseLib's package instructions.
