Three distinctions worth retaining

Owner versus recipient
The two example potions use target.Player for the recipient. Do not silently substitute Owner when adapting targeted content.
Request versus result
Drawing can return fewer cards than requested. DrawInternal checks prevention, remaining supplies, hand capacity, and combat state; it runs draw hooks and records history.
Configured amount versus literal
The example commands obtain amounts from DynamicVars. Dynamic-variable definitions and display text will be a separate lesson.

Computing available slots once and repeatedly drawing until full are different designs if on-draw effects remove or add cards. Keep this decision explicit when implementing the requested potion. Any repeated approach must handle a draw that makes no progress.
